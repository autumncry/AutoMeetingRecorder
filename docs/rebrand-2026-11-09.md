# AMR 品牌与安装修复

目标：统一公开名称 AutoMeetingRecorder（AMR）、北电数智蓝、Finder/Dock/通知图标、替换旧安装、私有 GitHub + MIT。

## 已观察的原因

应用程序里的旧版为 0.1.0，缺少 CFBundleIconFile 和图标资源；开发目录中的 0.1.1 已有图标。它们同时使用同一 bundle ID，导致目标查找有歧义。开发包的根目录时间仍是首次打包时间，旧构建过程只覆盖内部文件；系统图标缓存是否由此未更新仅是可能因素，不能当成已证实的唯一原因。

## 修复

- 显示名、可执行文件、包名、源码目标目录改为 AutoMeetingRecorder；简称 AMR。
- 保持内部 bundle ID `local.MeetingScribe` 和钥匙串服务 `local.MeetingScribe.api`，避免无意义地切断原权限与凭据引用。
- 旧设置验证后只复制一次到新的 Application Support 目录，原录音路径与配置 UUID 保持不变，不覆盖新设置。
- 图标改为 BEDI 蓝；主窗口、设置、菜单栏使用一致标识。应用启动时显式设置 NSApplication 图标。
- 打包改为新 staging bundle，检查资源与签名后替换产物，更新根目录时间。
- 安装脚本预检运行状态，备份并验证旧 app ZIP，再替换、注册新 app、注销旧副本注册；支持失败回滚。不会重置 TCC、删除录音或清空全局 Dock/Finder 缓存。
- 增加本地测试通知入口和系统解析图标检查脚本。

## 证据边界

迁移和原有逻辑通过自动测试后，仍要检查系统实际解析的图标与运行界面。新的测试通知需要系统通知权限；资源存在与签名通过不能冒充通知图标已在系统中显示。

## 本轮验证

- 53 项测试通过，包含旧配置迁移、保留 profile ID、现有配置优先、拒绝损坏的旧配置。
- 新构建和安装副本的 NSWorkspace 系统解析图标均渲染为正确的蓝色图标，并已实际查看 PNG。
- `/Applications/AutoMeetingRecorder.app` 已安装，旧 `/Applications/MeetingScribe.app` 备份后移除；签名验证通过。
- 从安装路径启动 QA 实例，实际查看新名称、主窗口蓝色设计、应用内图标和设置版本。没有开启录音或调用 ASR/LLM。
- 点击了本地测试通知入口；通知中心的自动化界面访问超时，未取得实际系统通知弹窗的视觉证据。不能把资源/窗口图标验证算作通知弹窗验收。用户可通过设置中的测试入口最终确认。
- QA 实例已退出，避免用户下次启动误入合成资料库。
