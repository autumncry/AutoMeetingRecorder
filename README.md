# MeetingScribe · 会记

个人使用的 macOS 会议录音、转写与纪要工具。原生 SwiftUI，音频与笔记保存在本机，ASR/LLM 使用你自己的接口。

## 打开

双击项目 `Builds/MeetingScribe.app`。可以复制到“应用程序”文件夹。本机构建使用 ad-hoc 签名，不需要付费 Apple 开发者账号，也没有做面向公众发行的公证。重新构建后 macOS 可能要求重新授权。

要求 macOS 14.2 或更新。本次产物为 Apple Silicon（arm64）。

## 首次配置

1. 设置 → ASR 模型：填写内网地址（例如 `http://服务器IP:8000/v1`）及服务端模型名称。Key 可留空；填写后点击“保存 Key”，密钥存入钥匙串。可以新建多个配置并设默认。
2. 选择“文件转写接口”或“聊天接口 + 音频”。聊天接口还可选择 `audio_url` / `input_audio` 两种 Base64 格式。用“选择音频测试”发送所选文件的前 5 秒，查看解析结果和原始响应。
3. 设置 → 总结模型：填写兼容的聊天接口、模型名和 Key，修改中文 Markdown 总结指令。可先测试连接。
4. 设置 → 录音：授予系统音频、麦克风、辅助功能权限，然后开启飞书自动检测。首次启动检测默认关闭，避免未经配置开始录音。
5. 可选择外部 Markdown 阅读器所用的文件夹作为资料库。切换资料库不会移动已有文件。

## 使用

- 手动录音：工具栏或菜单栏“开始录音”；快捷键 `⌘⇧R`。关闭主窗口不会停止录音。
- 自动检测：采用系统音频断言、进程归属与飞书窗口线索。候选需稳定 3 秒；确认离会后等待 8 秒。查询失败不视为离会。
- 疑似会议：先本地暂存并通知，选择“保留并继续”或“不录，丢弃”。120 秒未确认会自动清理。确认前不转写、不上传；拒绝后在观察到离开前不重复触发。
- 默认跟随飞书静音：只在明确读到自己的开麦控件时保留本地麦克风；未知/静音则只保留远端。未授权辅助功能或客户端控件不支持时可能需手动结束会议录音。
- 麦克风只在内存缓冲约 2 秒后才写盘，静音/暂停/停止会丢弃未验证尾部。这可减少延迟误录，但可能缺少末尾约 2 秒本人发言；不能保证捕捉到两次轮询之间的快速静音切换。实际静音边界仍需实会验收。
- 蓝牙、有线和外放：选与飞书相同的麦克风。系统捕获包含其他应用声音，不是飞书独占音轨。首版没有 WebRTC 回声消除，外放可能重复收音。
- 设备/格式变化、断开或音频回调异常：停止采集并保存已有音轨，提示后可重新开始录音；首版不宣称无缝热切换。
- 导入录音：工具栏“导入录音”，支持系统可解码的 WAV、M4A、MP3、CAF 等。原文件复制保留。OGG/WebM 等若系统无法解码，请先导出 MP3/WAV。
- 分享链接：支持音频直链，以及 `plaud.cn` 页面中可直接提取的音频链接。不登录、不执行网页脚本。私有、过期或动态页面无法提取时，先在 PLAUD 导出音频再导入；未对你的实际分享链接做兼容性承诺。
- 处理与导出：可以用另一个 ASR 重新转写，旧版本保留；选择版本后可以重新总结。点击转写时间跳转播放。Markdown 可编辑，也可在 Finder 中直接打开。

## 文件与错误处理

每场会议一个目录：`meeting.json`、原始音轨 `system.caf` / `microphone.caf`（启用时）、混音 `recording.wav`、`transcript.<版本>.md/json`、当前 `transcript.md`、`summary.md`。重新总结保留旧 summary 副本。

录音先落盘再上传。网络请求失败有有限重试，最终失败后保留音频和已完成转写，菜单中可重试。应用异常退出后，待确认录音在重新打开该资料库时清理；已确认中断录音保留原始音轨，可通过文件导入恢复转写。不要把资料库放进自动清理的临时目录。

设置中的 API 地址决定数据发往哪里：音频发往 ASR，转写文本发往 LLM；没有内置云端备用服务。HTTP 用于用户指定的内网接口，HTTPS 仍进行正常证书验证。

## 开发

所有源代码、测试、资源和脚本都在项目的 `code/` 下。

```sh
cd code
swift test
./script/build_and_run.sh --build  # Builds/MeetingScribe.app
./script/build_and_run.sh         # 构建并打开
```

构建脚本在 app 仍运行时会拒绝覆盖，请先保存录音并退出。支持 `--qa`（项目内独立测试资料库）、`--verify`、`--debug`、`--logs`。文档在 `docs/`，验证日志在 `Validation/`，构建产物在 `Builds/`。

编译与合成测试通过不能替代设备验收。尚需你提供 H800 接口配置并授予系统权限，验证一次真实飞书会议，以及实际 PLAUD 分享链接。
